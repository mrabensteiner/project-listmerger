\chapter{Library User Guide}
\label{chap:libuser}

This section addresses to library user that want to include the
ListMerger library in a larger software project. Some general remarks on
the usage of the library are already conducted in
Appendix~\ref{chap:enduser}. This chapter is more focused on the
initalisation.






\section{Examples}

Within the code, a simple and an extended example of implementations are
delivered and can be found in the \fname{/src/example} folder. The
simple example (\fname{simple.html} and \fname{simple.js}) demonstrate a
minimal setup. The extended example (\fname{index.html} and
\fname{main.js}) is a showcase of nearly all features implemented in the
library. To ensure the correct functioning of some elements, certain CSS
styling rules are highly recommended and can be found in
\fname{listmerger.css}. Further styling recommendations can be found
linked in the examples (\fname{style.css}).





\section{Initialising}
\label{sec:libu-init}

To initialise the library within an application, the \vname{init()}
function needs to be called. This function has four parameters:
\begin{itemize}
  \item \vname{items}: A data structure of items and lists, further
    described in Section~\ref{sec:libu-datastructure}
  \item \vname{templates}: The templates for rendering items, further
    described in Section~\ref{sec:libu-templates}.
  \item \vname{selectors}: Identifiers for HTML class names, IDs,
    attributes, etc., further described in Section~\ref{sec:libu-selectors}.
  \item \vname{history_callback}: A function that is called when changes
    are made.
\end{itemize}

The parameter \vname{items} is the only mandatory one, the others are
optional. When they are left empty, this results in blank templates,
standard selectors, respectively an empty function for the callback.

Items have to be handed over in an object that needs to contain at least
a \vname{merged} key and an \vname{originlists} key. The first can be an
empty array, or already contain items. The second one needs to be filled
with the lists as objects with some metadata (\vname{id}, \vname{name},
etc.) and an \vname{items} key, which also contains an array of items,
as seen in Listing~\ref{list:itemslist}.

One item needs to have at least an \vname{id}. This ID is also used as
ID in the HTML DOM. The other keys are optional and need to be included
depending on whether they are needed in the user-defined templates.
Arrays (like images) are always merged together in the merging process.

During runtime, the data is stored in the same format on the stack. When
finished, it can be suitable to store the data structure as a JSON file,
or to send it in this format to a REST API. More details about this are
in Section~\ref{sec:libu-saving}.







\section{Templating}
\label{sec:libu-templates}

Templates define how the items appear in the lists. When initialising,
the \vname{template} parameters is a string-string pair with up to four
keys. These are:
\begin{itemize}
  \item \vname{"item"}: The content of an item in the list, will be
    surrounded by a \elname{details} element.
  \item \vname{"dialog"}: The content shown left and right in a merge
    dialogue, representing the items to merge.
  \item \vname{"merge"}: The middle column in merge dialogue, containing
    form items for the future mergeitem.
  \item \vname{"draghandle"}: Option to add an element to an item which
    functions as handle to drag.
\end{itemize}
An item template contains ideally a \elname{summary} element, so that the
expand-and-collapse functionality is given. In the merge dialogue, the
\vname{name} attribute of form elements need to be identical with the
keys used in an item to be recognized correctly. 


To show an example, the following snippet for \vname{item} with the data
example from Listing~\ref{list:itemslist}:
\begin{samepage}
\begin{lstlisting}[%
  language=HTML,
]
<summary>{{title}}</summary>
{{author}}: {{description}}

{{#images}}
  <img src="{{.}}"/>
{{/images}}
\end{lstlisting}
\end{samepage}

renders to:

\begin{samepage}
\begin{lstlisting}[%
  language=HTML,
]
<details id="li1it1">
  <summary>Item 1</summary>
  Martin Rabensteiner: This is the first item in the list.

  <img src="images/screenshot1.png"/>
  <img src="images/screenshot2.png"/>
</details>
\end{lstlisting}
\end{samepage}

\section{Saving}
\label{sec:libu-saving}
The current state of the list can always be received with the
\vname{getAllItems()} function. This returns a JavaScript object in the
same format as described in Section~\ref{sec:libu-datastructure}, and
additionally a \vname{version} field to indicate changes in the schema.
The version at release is \vname{v0.1}. For changes, please conduct the
changelog in the GitHub repository.

The \vname{history_callback} function can be a helpful tool when the
state should always be saved in real time. A function can be handed over
during initalisation. The function can have the boolean parameter
\vname{is_new}, which is true when a user action has happened, and false
when an action was triggered from an undo or redo action.







\section{Inline Editing}
\label{sec:libu-editing}

\begin{figure}[tp]
\centering
\includegraphics[frame,keepaspectratio,width=\linewidth,height=\halfh]
{images/edit-i.png}
\caption[Inline Editing]{%
An example of inline editing, which is currently active for
\uiname{Category} and \uiname{Images}. The image editing is not part of
the library itself but can be taken from the main example.
\imgcredit{Screenshot by Martin Rabensteiner.}
}
\label{fig:inline-edit}
\end{figure}



Fields of items can be configured to be editable inline, as seen in
Figure~\ref{fig:inline-edit}. For text-only fields, the
\vname{contenteditable} attribute \parencite{mdn-contenteditable} should
be set to \vname{"plaintext-only"}. Setting it to \vname{"true"} is also
sufficient for the functionality, but can lead to unexpected behaviour
when dragging an image over the field.

To use a \elname{select} element for editing, the CSS class
\cname{selectedit} can be put on a \elname{span} element to replace its
content. The \elname{span} needs to have some \vname{data-*} attributes
to build the select box. These attributes are:
\begin{itemize}
  \item \vname{data-name}: Is used as \vname{name} for the
    \elname{select} element and for storing to the item, therefore it
    should be one of the already set children of the item.

  \item \vname{data-options}: Needs to have the possible options of the
    select box. It can be either a one-dimensional array, or an object
    with key-value pairs. If it is an object, the key and values are
    used as they are, othervise the single values are used for both.

  \item \vname{data-values}: Can be a single value, or comma-separted
    the selected values. Valid examples are:
    \begin{itemize}
      \item \lstinline!1,2,3,4!
      \item \lstinline!["John", "Max", "Mario"]!
      \item \lstinline!{"0": "Very Low", "1": "Low", "2": "Medium", "3": "High", "4": "Very High"}!
    \end{itemize}
  
  \item \vname{data-mode}: By default, the select box is displayed as
    single select. When the mode is \vname{multiple}, the
    \vname{multiple} attribute is added to the \elname{select} element
    as well. Another option for this attribute is \vname{class}, to
    change the class of this element to a specific mode, for example to
    represent colors or icons of the current value.
  
  \item \vname{data-class}: If the mode is set to \vname{class}, this
    value is used as CSS class prefix. When the selection is changed,
    the class consisting of the prefix and the selected value is added
    to this element. Other classes with this prefix are remove on an
    input change.
\end{itemize}






\section{Draghandle}
\label{sec:libu-draghandle}
A draghandle can be added to an item to allow only arranging, when
dragging the item. This can be useful when the design requires a
stronger distinction between merging and arranging items, for example
when there is no space between two items or the separating bar between
two items should not be shown. Some elements, for example \elname{img}
have a draggable attribute by default. For other elements it is
necessary to add the attribute \lstinline!draggable="true"!. The snippet
below shows a template example with the already included icon:
\begin{samepage}
\begin{lstlisting}[%
  language=HTML,
]
<img class="draghandle" src="icons/dragicon.svg"/>
\end{lstlisting}
\end{samepage}
